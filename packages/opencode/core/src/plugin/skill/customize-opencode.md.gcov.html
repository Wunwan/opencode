       8              : # Customizing opencode
       9              : 
      10              : opencode validates its own config strictly and refuses to start when a field
      11              : is wrong. The shapes below cover the common surface area, but they are a
      12              : **summary, not the source of truth**.
      13              : 
      14              : ## Full schema reference
      15              : 
      16              : The authoritative list of every config option — with field types, enums,
      17              : defaults, and descriptions — lives in the published JSON Schema:
      18              : 
      19              : **<https://opencode.ai/config.json>**
      20              : 
      21              : If a field is not documented in this skill, or you need to confirm an exact
      22              : shape before writing config, **fetch that URL and read the schema directly**
      23              : rather than guessing. opencode hard-fails on invalid config, so the cost of a
      24              : wrong shape is a broken startup.
      25              : 
      26              : Independently, every `opencode.json` should declare
      27              : `"$schema": "https://opencode.ai/config.json"` so the user's editor catches
      28              : mistakes as they type.
      29              : 
      30              : ## Applying changes
      31              : 
      32              : Config is loaded once when opencode starts and is not hot-reloaded. After
      33              : saving changes to `opencode.json`, an agent file, a skill, a plugin, or any
      34              : other config-time file, **tell the user to quit and restart opencode** for
      35              : the changes to take effect. The running session will keep using the
      36              : already-loaded config until then.
      37              : 
      38              : ## Where files live
      39              : 
      40              : | Scope                         | Path                                                                                                                      |
      41              : | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
      42              : | Project config                | `./opencode.json`, `./opencode.jsonc`, or `.opencode/opencode.json` (opencode walks up from the cwd to the worktree root) |
      43              : | Global config                 | `~/.config/opencode/opencode.json` (NOT `~/.opencode/`)                                                                   |
      44              : | Project agents                | `.opencode/agent/<name>.md` or `.opencode/agents/<name>.md`                                                               |
      45              : | Global agents                 | `~/.config/opencode/agent(s)/<name>.md`                                                                                   |
      46              : | Project commands              | `.opencode/command/<name>.md` or `.opencode/commands/<name>.md`                                                           |
      47              : | Global commands               | `~/.config/opencode/command(s)/<name>.md`                                                                                 |
      48              : | Project skills                | `.opencode/skill(s)/<name>/SKILL.md`                                                                                      |
      49              : | Global skills                 | `~/.config/opencode/skill(s)/<name>/SKILL.md`                                                                             |

     161              : ## Skills
     162              : 
     163              : opencode's skill loader scans for `**/SKILL.md` inside skill directories. The
     164              : file is named `SKILL.md` exactly, and lives in its own folder named after the
     165              : skill:
     166              : 
     167              : ```
     168              : .opencode/skills/my-skill/SKILL.md

     173              : ```markdown
     174              : ---
     175              : name: my-skill
     176              : description: One sentence covering what this skill does AND when to trigger it. Front-load the literal keywords or filenames the user is likely to say.

     192              : ## References
     193              : 
     194              : References make local directories and Git repositories outside the active
     195              : project available as supporting context. Configure them under `references`,
     196              : keyed by the alias used in `@` autocomplete:
     197              : 
     198              : ```json
     199              : {
     200              :   "references": {
     201              :     "docs": {
     202              :       "path": "../product-docs",
     203              :       "description": "Use for product behavior and terminology"
     204              :     },
     205              :     "effect": {
     206              :       "repository": "Effect-TS/effect",
     207              :       "branch": "main",
     208              :       "description": "Use for Effect implementation details"
     209              :     }
     210              :   }
     211              : }
     212              : ```
     213              : 
     214              : Local `path` values may be relative to the declaring config, absolute, or use
     215              : `~/`. Git `repository` values accept Git URLs, host/path references, and GitHub
     216              : `owner/repo` shorthand; `branch` is optional. Both forms support optional
     217              : `description` and `hidden` fields.
     218              : 
     219              : - Only references with a `description` are advertised to agents in system context.
     220              : - `hidden: true` removes a reference from TUI `@` autocomplete only. It remains available to agents and by direct path.
     221              : - Reference directories are automatically allowed through the external-directory boundary; normal read/edit/tool permissions still apply.
     222              : - String shorthand is supported: use `"docs": "../docs"` for local paths or `"effect": "Effect-TS/effect"` for Git repositories.

     305              : - `$ARGUMENTS` is replaced with everything the user typed after the command; `$1`, `$2`, … pull individual positional arguments.
     306              : - Optional: `description`, `agent`, `model`, `variant`, `subtask`.

     308              : ## Plugins
     309              : 
     310              : `plugin:` is an array. Each entry is one of:
     311              : 
     312              : ```json
     313              : "plugin": [
     314              :   "opencode-gemini-auth",            // npm spec, latest
     315              :   "opencode-foo@1.2.3",              // npm spec, pinned
     316              :   "./local-plugin.ts",               // file path, relative to the declaring config
     317              :   "file:///abs/path/plugin.js",      // file URL
     318              :   ["opencode-bar", { "key": "val" }] // tuple form with options
     319              : ]
     320              : ```
     321              : 
     322              : Auto-discovered plugins (no config entry needed): any `*.ts` or `*.js` file in
     323              : `.opencode/plugin/` or `.opencode/plugins/`.
     324              : 
     325              : A plugin module exports `default` (or any named export) of type
     326              : `Plugin = (input: PluginInput, options?) => Promise<Hooks>`. The export is a
     327              : function, not a plain object literal, and the function returns an object
     328              : (return `{}` if there is nothing to register).
     329              : 
     330              : ```ts
     331              : import type { Plugin } from "@opencode-ai/plugin"

     333              : export default (async ({ client, project, directory, $ }) => {
     334              :   return {
     335              :     config: (cfg) => {
     336              :       // cfg is the live merged config; mutate fields here.
     337              :     },
     338              :     "tool.execute.before": async (input, output) => {
     339              :       // mutate output.args before the tool runs
     340              :     },
     341              :   }
     342              : }) satisfies Plugin
     343              : ```
     344              : 
     345              : Hook surface (mutate `output` in place; return `void`):
     346              : 
     347              : - `event(input)`: every bus event
     348              : - `config(cfg)`: once on init with the merged config
     349              : - `chat.message`, `chat.params`, `chat.headers`
     350              : - `tool.execute.before`, `tool.execute.after`
     351              : - `tool.definition`
     352              : - `command.execute.before`
     353              : - `shell.env`
     354              : - `permission.ask`
     355              : - `experimental.chat.messages.transform`, `experimental.chat.system.transform`,
     356              :   `experimental.session.compacting`, `experimental.compaction.autocontinue`,
     357              :   `experimental.text.complete`

     362              : ## MCP servers
     363              : 
     364              : `mcp:` is an object keyed by server name. Each server is discriminated by
     365              : `type`:
     366              : 
     367              : ```json
     368              : {
     369              :   "mcp": {
     370              :     "playwright": {
     371              :       "type": "local",
     372              :       "command": ["npx", "-y", "@playwright/mcp"],
     373              :       "enabled": true,
     374              :       "environment": { "BROWSER": "chromium" }
     375              :     },
     376              :     "github": {
     377              :       "type": "remote",
     378              :       "url": "https://...",
     379              :       "enabled": true,
     380              :       "headers": { "Authorization": "Bearer {env:GITHUB_TOKEN}" }
     381              :     },
     382              :     "old-server": { "enabled": false }
     383              :   }
     384              : }
     385              : ```
     386              : 
     387              : `command` is an array of strings. `environment` sets environment variables for
     388              : a local MCP server. `type` is required. Use `enabled: false` to
     389              : disable a server inherited from a parent config. String values such as header
     390              : tokens support `{env:VAR}` interpolation (and `{file:path}`); the shell-style
     391              : `${VAR}` is not substituted.
     392              : 
     393              : ## Permissions
     394              : 
     395              : ```json
     396              : "permission": {
     397              :   "edit": "deny",
     398              :   "bash": { "git *": "allow", "rm *": "deny", "*": "ask" },
     399              :   "external_directory": { "~/secrets/**": "deny", "*": "allow" }
     400              : }
     401              : ```
     402              : 
     403              : Actions: `"allow"`, `"ask"`, `"deny"`.
     404              : 
     405              : Per-tool value forms: `"allow"` shorthand (treated as `{"*": "allow"}`), or an
     406              : object `{ pattern: action }`. Within an object, **insertion order matters**.
     407              : opencode evaluates the LAST matching rule, so put broad rules first and narrow
     408              : rules last.
     409              : 
     410              : `permission: "allow"` (a string at the top level) is shorthand for "allow
     411              : everything" and is rarely what the user wants.
     412              : 
     413              : Known permission keys: `read, edit, glob, grep, list, bash, task,
     414              : external_directory, todowrite, question, webfetch, websearch, lsp, doom_loop,
     415              : skill`. Some of these (`todowrite,
     416              : question, webfetch, websearch, doom_loop`) only accept a flat
     417              : action, not a per-pattern object.
     418              : 
     419              : `external_directory` patterns are filesystem paths (use `~/`, absolute paths,
     420              : or globs like `~/projects/**`).
     421              : 
     422              : Per-agent `permission:` overrides top-level `permission:`. Plan Mode lives on
     423              : the `plan` agent's permission ruleset (`edit: deny *`).
     424              : 
     425              : ## Escape hatches
     426              : 
     427              : When a user's config is broken and opencode won't start, these env vars help:
     428              : 
     429              : - `OPENCODE_DISABLE_PROJECT_CONFIG=1`: skip the project's local `opencode.json`
     430              :   and start from globals only. Run from the project directory, opencode loads,
     431              :   the user edits the broken file, then they restart without the flag.
     432              : - `OPENCODE_CONFIG=/path/to/file.json`: load an additional explicit config.
     433              : - `OPENCODE_CONFIG_CONTENT='{"$schema":"https://opencode.ai/config.json"}'`:
     434              :   inject inline JSON as a final local-scope merge.
     435              : - `OPENCODE_DISABLE_DEFAULT_PLUGINS=1`: skip default plugins.
     436              : - `OPENCODE_PURE=1`: skip external plugins entirely.
     437              : - `OPENCODE_DISABLE_EXTERNAL_SKILLS=1`,
     438              :   `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1`: skip the external skill scans under
     439              :   `~/.claude/` and `~/.agents/`.
     440              : 
     441              : ## When proposing edits
     442              : 
     443              : - Validate against the schema before writing. If you are unsure of a field's
     444              :   exact shape, or the field is not covered in this skill, fetch
     445              :   `https://opencode.ai/config.json` and read the schema rather than guessing.
     446              : - Preserve `$schema` and any existing fields the user did not ask to change.
     447              : - For agent, command, skill, and plugin definitions, prefer creating new files
     448              :   in the correct location over inlining everything in `opencode.json`.
     449              : - If the user's existing config is malformed, point them at the env-var escape
     450              :   hatches above so they can edit from inside opencode without breaking their
     451              :   session.
     452              : - After saving any config change, remind the user to quit and restart opencode
     453              :   — running sessions keep using the already-loaded config.
